# Project Rules and Guidelines

## 1. Design Fidelity (Strict Rule)
The newly created website in ReactJS MUST look exactly similar to the provided HTML files.
- Word for word.
- Color for color.
- Inch for inch.
- Pixel for pixel.
*Do not change any fonts, colors, or structural layouts.*

## 2. Content Architecture
### Dynamic Content
- **Actualités**: Blog posts.
- **Événements**: Similar to blog posts, but with a different design style.
These will be managed dynamically via a backend CMS / Dashboard.

### Static Content
- **Other Pages**: General information (Word of the Director, Organization Structure, etc.) will be hard-coded from the beginning just as they are in the HTML prototype.

## 3. Technology Stack
- **Frontend**: Next.js (ReactJS)
- **Styling**: Vanilla CSS. The original `index-DsSqZW0z.css` must be used globally. **Do not use TailwindCSS.**
- **Backend / CMS**: Next.js API Routes + SQLite Database via Prisma ORM for managing dynamic blog posts and events.

## 4. Work Tracking
- Create a `gstsm` folder as the root for the React application.
- Keep notes, rules, and information in this `obsidian notes` directory.
- Maintain an Implementation Plan and Checklist to track progress and avoid mistakes.
